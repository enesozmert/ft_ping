## MISRA — Kategori Özeti

| Kategori          | Açıklama                                                        |
|-------------------|------------------------------------------------------------------|
| **Mandatory**     | İhlal **kesinlikle** kabul edilmez.                              |
| **Required**      | İhlal yalnızca yazılı **deviation** ile kabul edilir.            |
| **Advisory**      | İhlal proje politikasına bağlıdır; kayıt altına alınmalıdır.     |

---

## MC-01: Standart C Environment (Directive 1.x)

- 1.1: Implementation, ISO/IEC 9899:2011 (C11) sınırlarına uymalı.
- 1.2: Language extensions kullanılmamalı (`__attribute__`, GCC built-in,
  vb.). Kullanılırsa `deviation` belgelenmeli.
- 1.3: `undefined behavior` yaratacak yapılar kullanılmamalı.

---

## MC-02: Unused Code (Rule 2.x)

- 2.1: Unreachable code yasak.
- 2.2: Dead code yasak (etkisi olmayan ifadeler).
- 2.3: Unused `typedef` yasak.
- 2.4: Unused `tag` (struct/union/enum) yasak.
- 2.5: Unused `macro` yasak.
- 2.6: Unused `label` yasak.
- 2.7: Function’ın kullanılmayan parametresi yasak.

---

## MC-03: Comments (Rule 3.x)

- 3.1: `/*` ve `*/` karakter dizileri **comment** içinde olmamalı.
- 3.2: Line-splice (`\` ile satır birleştirme) `//` yorumda olmamalı.

---

## MC-04: Character Sets and Lexical Conventions (Rule 4.x)

- 4.1: Octal ve hexadecimal escape sequence’lar **kapatılmış** olmalıdır.
- 4.2: Trigraph’lar yasak.

---

## MC-05: Identifiers (Rule 5.x)

- 5.1: External identifier’lar **31 karakter** içinde benzersiz olmalı.
- 5.2: Aynı scope’ta farklı tipler aynı isimde olmamalı.
- 5.3: Inner-scope identifier, outer-scope identifier’ı gizlememeli (no
  shadowing).
- 5.4: Macro identifier’ı 63 karakter içinde benzersiz olmalı.
- 5.5: Macro ile non-macro identifier aynı isimde olmamalı.
- 5.6 / 5.7: `typedef` ve `tag` isimleri benzersiz olmalı.
- 5.9: Internal linkage’lı identifier benzersiz olmalı.

---

## MC-06: Types (Rule 6.x)

- 6.1: Bit-field’lar **uygun tipte** olmalı (`signed/unsigned int` yerine
  `_Bool` veya açıkça belirtilmiş tip).
- 6.2: Single-bit named bit-field’lar **signed** olmamalı.

---

## MC-07: Literals & Constants (Rule 7.x)

- 7.1: Octal constant yasak (`0` hariç).
- 7.2: Integer constant `u`/`U` suffix ile **unsigned** olmalı (uygun
  yerde).
- 7.3: `l` (lowercase) suffix yasak; sadece `L` kullanılmalı.
- 7.4: String literal **modifiable** olmamalı; `const char *` ile
  saklanmalı.

---

## MC-08: Declarations & Definitions (Rule 8.x)

- 8.1: Function tipleri **explicit** olmalı (implicit `int` yasak).
- 8.2: Function declaration **prototype** kullanmalı.
- 8.4: External objelerin **declaration**’u, **definition**’dan önce
  görünür olmalı.
- 8.5: External object yalnızca **bir defa** declare edilmeli.
- 8.6: External object yalnızca **bir defa** define edilmeli.
- 8.7: Yalnızca tek translation unit’ta kullanılan global,
  **`static`** olmalı.
- 8.9: Yalnızca bir fonksiyonda kullanılan global, **block scope**’a
  alınmalı veya `static` olmalı.
- 8.13: Pointer parametre, fonksiyon değiştirmiyorsa `const`-qualified
  olmalı.

---

## MC-09: Initialization (Rule 9.x)

- 9.1: Otomatik storage’lı objeler **kullanılmadan önce** initialize
  edilmeli.
- 9.2: Aggregate / union initializer **brace** ile sarılmalı.
- 9.3: Array partial-init varsa **tüm** elemanlar açıkça init edilmeli.

---

## MC-10: Essential Type Model (Rule 10.x)

- 10.1: Operand’lar **uygun essential type** ile kullanılmalı.
- 10.3: `signed/unsigned` karışımında implicit conversion yasak.
- 10.4: Karşılaştırmada operand’lar aynı essential type’ta olmalı.
- 10.5 / 10.6 / 10.7 / 10.8: Cast’ler **kontrollü** olmalı; loss of
  precision veya signedness değişimi yasak.

---

## MC-11: Pointer Type Conversions (Rule 11.x)

- 11.1: Function pointer ↔ object pointer cast yasak.
- 11.2: Incomplete type pointer cast yasak (gerekçeli istisnalar hariç).
- 11.3: Object pointer cast’i **alignment**’ı bozmamalı.
- 11.4: Integer ↔ pointer cast yasak (network ve hardware register
  istisnaları **deviation** gerektirir).
- 11.5: `void *` → object pointer cast’i sınırlandırılmıştır.
- 11.8: `const`/`volatile` qualifier’lar cast ile **kaldırılmamalıdır**.

---

## MC-12: Expressions (Rule 12.x)

- 12.1: Operator precedence **parantez** ile netleştirilmeli.
- 12.2: Right-hand operand’ı yan etkisi olan operator’ler dikkatli
  kullanılmalı.
- 12.3: `,` (comma) operator yasak (for-init istisnası kontrollü).

---

## MC-13: Side Effects (Rule 13.x)

- 13.1: Initializer list’te yan etki yasak.
- 13.2: Bir ifadenin sonucu, **evaluation order**’a bağlı olmamalı.
- 13.3: `++` / `--` ile başka yan etkiler aynı ifadede olmamalı.
- 13.5: `&&` / `||` sağ operandında yan etki yasak.

---

## MC-14: Control Statement Expressions (Rule 14.x)

- 14.1: `for` döngü kontrol değişkeni **floating point** olmamalı.
- 14.2: `for` döngüsü **iyi tanımlı** olmalı (init, test, update tek
  variable üzerinde).
- 14.3: Controlling expression **invariant** olmamalı.
- 14.4: Controlling expression **boolean** olmalı.

---

## MC-15: Control Flow (Rule 15.x)

- 15.1: `goto` yasak.
- 15.2: `goto` ileriye doğru olmalı (15.1 ihlali yoksa).
- 15.5: Function’ın **tek** `return` noktası olmalı (advisory).
- 15.6: `if/else/while/for/switch` gövdesi **brace** ile sarılmalı.
- 15.7: `if ... else if ... else` zincirinde son `else` bulunmalı.

---

## MC-16: Switch Statements (Rule 16.x)

- 16.1: `switch` iyi yapılandırılmış olmalı.
- 16.3: Her `case` `break` ile sonlanmalı (fallthrough yasak).
- 16.4: Her `switch` **`default`** içermeli.
- 16.5: `default` ya en başta ya en sonda olmalı.

---

## MC-17: Functions (Rule 17.x)

- 17.1: `<stdarg.h>` kullanımı sınırlı (gerekçeli).
- 17.2: Function **recursion** yasak (advisory’den required’a yükseldi).
- 17.3: Function declaration olmadan çağrı yasak.
- 17.4: Function tüm path’lerde `return` etmeli (non-void).
- 17.7: Non-void return değeri **kullanılmalı** ya da `(void)` cast ile
  açıkça atılmalı.

---

## MC-18: Pointers & Arrays (Rule 18.x)

- 18.1: Pointer arithmetic, **array bounds** içinde kalmalı.
- 18.2: İki pointer arasındaki fark, aynı array içindeki elemanlara
  işaret etmeli.
- 18.4: `+`, `-`, `+=`, `-=` operator’leri pointer’a uygulanmamalı (advisory).
- 18.5: `>2` seviye pointer indirection yasak (advisory).
- 18.6: Otomatik storage’lı objelerin adresi, scope dışına çıkmamalı.
- 18.7: Flexible array member’lar yalnızca dinamik allocate edilmeli.

---

## MC-19: Overlapping Storage (Rule 19.x)

- 19.1: Object kendisiyle veya başka objeyle **overlap** etmemeli.
- 19.2: `union` kullanımı sınırlı (advisory).

---

## MC-20: Pre-processing Directives (Rule 20.x)

- 20.1: `#include` directive’i, dosyada **diğer pre-processing
  directive**’lerinden önce gelmeli.
- 20.4: Reserved identifier `#define` ile yeniden tanımlanmamalı.
- 20.5: `#undef` kullanımı yasak.
- 20.7: Macro parametre, replacement list’te **parantezli** olmalı.
- 20.10: `#` ve `##` operator’leri yasak.
- 20.12: Macro parametre hem `#`/`##` hem de normal expansion’a uğramamalı.

---

## MC-21: Standard Libraries (Rule 21.x)

- 21.1: Reserved identifier `#define` / `#undef` yasak.
- 21.3: `<stdlib.h>` `malloc`/`calloc`/`realloc`/`free` kullanımı
  sınırlı (deviation gerekli).
- 21.6: `<stdio.h>` Input/Output fonksiyonları kullanımı sınırlı.
- 21.7: `atof`, `atoi`, `atol`, `atoll` kullanımı yasak.
- 21.8: `abort`, `exit`, `getenv`, `system` kullanımı yasak.
- 21.10: `<time.h>` `time` ve `localtime` kullanımı sınırlı.
- 21.13: `<ctype.h>` fonksiyonlarına `EOF` veya `unsigned char` dışında
  argüman geçilmemeli.

---

## MC-22: Resources (Rule 22.x)

- 22.1: Dinamik allocate edilen kaynak **explicit** free edilmeli.
- 22.2: Allocate edilmemiş objeye `free` çağrılmamalı.
- 22.3: Aynı dosya, aynı anda farklı stream’lerden açılmamalı.

---

## ft_ping — MISRA Deviation Notları

ft_ping projesi **gerçek raw socket** ve **network protocol** ile
çalıştığından bazı kuralların **deviation** gerektirmesi beklenir:

| Rule  | Deviation Gerekçesi                                                |
|-------|--------------------------------------------------------------------|
| 11.4  | `sockaddr` cast’leri (POSIX socket API zorunluluğu)                |
| 21.3  | `malloc/free` raw packet buffer için                               |
| 21.6  | `printf` ailesi — subject explicit izin veriyor                    |
| 21.10 | `gettimeofday` / `clock_gettime` RTT ölçümü için                   |
| 17.7  | `setsockopt`, `signal` gibi fonksiyon dönüşleri kontrol edilmeli   |
